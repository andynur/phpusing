## Store upload

1. Use [LISTING.md](../store/LISTING.md) for descriptions and permission disclosures.
2. Upload the five `en-store-*` images to the English locale and the five `id-store-*` images to Indonesian, in numerical order.
3. Use the shared `store-promo-*` pair for the promotional slots. Google's image guidance says promotional images are not locale-specific; EN/ID alternatives are supplied for other marketing channels or a deliberate audience choice.
4. Use `store-icon-128.png` for the listing icon. The extension package icons remain owned by `tools/icons/render.sh`; align the packaged 128 px icon's padding with this export before publishing.
5. Review the actual dashboard previews before submitting. Assets do not establish store acceptance or publication.

Sizes and locale behavior checked against [Chrome Web Store image guidance](https://developer.chrome.com/docs/webstore/images) on 2026-10-25. The screenshot canvas is full bleed with square corners. The shared promo artwork uses only the brand name and mark, in keeping with the guidance to minimize text.

## Screenshot provenance

The frames render the actual built popup/report HTML using the existing synthetic fixtures in `tools/store-shots/stub.js`. They are staged product demonstrations, not live scan results or evidence of security coverage. Each screenshot labels the example data. Sequence: consent, progress, priority findings, expanded report, settings in dark mode. The surrounding headlines are marketing captions, not extension UI.

No scanned secrets or customer data are used. Only key names appear in example evidence. No UI artwork is generated by AI. The existing raw captures under `docs/store/screenshots/` are preserved.

## Regenerate

From the repository root, with Node/pnpm, Python 3 and Google Chrome installed:

```sh
pnpm build
python3 tools/marketing/render.py
pnpm exec prettier --write docs/marketing/index.html docs/marketing/manifest.json
```

Set `CHROME` to the browser executable on other platforms. The renderer uses a temporary Chrome profile and a loopback-only HTTP server on an available port, then removes its temporary files. No dependency is added to the extension. It checks every PNG's dimensions and writes the gallery and manifest. Appearance can vary slightly with platform fonts. Marketing copy/layout sources are in `tools/marketing/render.py`.

## Brand use

- Preserve the lowercase name **phpusing** and the existing dizzy-head mark. Never substitute PHP's logo or the elePHPant.
- Brand violet `#5B45D6`, warm paper `#F7F6F2`, ink `#1C1B22`; Arial/system sans for these exports. Red is reserved for finding severity.
- Leave at least one quarter of the mark's width as clear space in new compositions. Do not distort the mark or add alarm badges to marketing lockups.
- Keep copy calm, specific and owner-focused. Do not promise complete protection, guaranteed safety, response times, store availability or upcoming v0.2 features.
- Until publication, use “View the project” / “Lihat proyek”, pointing to the repository. Add a store install link only after it exists.

## Validation boundary

PNG dimensions are checked during rendering; representative EN/ID screenshots, banners and promo tiles are visually inspected. `pnpm check` validates the shared application worktree separately. Manual real-site/WAF tests, actual permission prompts, clipboard behavior and Chrome Web Store acceptance remain release checks.

Validation on 2026-10-25: all 21 PNG dimensions passed; both locale sequences contain five screenshots; representative EN/ID consent, progress, verdict, expanded report, dark settings, banners and promo exports were inspected visually. `pnpm check` passed all six stages on the shared working tree; `git diff --check` passed.
